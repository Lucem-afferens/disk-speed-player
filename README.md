# Disk Play

**[Открыть плеер](https://lucem-afferens.github.io/disk-speed-player/)**

Мобильный плеер публичных видео и папок Яндекс Диска. Статическое приложение для GitHub Pages: HTML, CSS и JavaScript, без серверной части, внешних библиотек и аналитики. Опубликованный плеер работает и при выключенном Mac; устройству просмотра нужен доступ к GitHub Pages и Яндекс Диску.

## Использование

1. На Яндекс Диске выберите видео или папку → **Поделиться**. Доступ к скачиванию должен быть разрешён.
2. Откройте страницу плеера, вставьте публичную ссылку и нажмите **Открыть**.
3. Первое видео из открытой папки автоматически появляется в плеере с первым кадром. Для начала просмотра нажмите ▶ или выберите другое видео. Скорость находится рядом со звуком, в том числе в развёрнутом плеере.
4. Для другой папки вставьте новую ссылку и нажмите **Открыть**. Предыдущее видео останавливается сразу, даже если новая папка пустая или недоступна.
5. Уже скачанные видео открываются кнопками **«Выбрать папку»** и **«Выбрать видео»**. Папка собирается в один плейлист вместе со вложенными папками; можно выбрать и отдельные ролики, в том числе с внешнего диска. Браузер читает файлы сам, они никуда не отправляются. После обновления страницы папку нужно выбрать снова: браузер не отдаёт приложению постоянный путь.

При открытом видео **пробел — воспроизведение / пауза**, в том числе после нажатия кнопок скорости, звука и полного экрана, изменения ползунков и галочек. Удержание пробела переключает воспроизведение только один раз; отпускание не повторяет действие последней кнопки. В полях ввода пробел вводит текст. Для обычного нажатия выбранной кнопки с клавиатуры остаётся **Enter**. Проверка в Chromium и WebKit: `npm run test:keyboard`.

**«Очистить папку и видео»** рядом со ссылкой полностью освобождает плеер: останавливает воспроизведение и загрузки, убирает список, последнюю ссылку и временные описания потоков Safari из памяти и IndexedDB. Очистка действует во всех открытых вкладках Disk Play этого браузера. После подтверждения можно сразу вставить новую ссылку, без перезапуска и ручной очистки браузера. История и отметки сохраняются; галочка в диалоге удаляет и их. Скорость и настройка автоперехода сохраняются. Если хранилище недоступно, приложение сообщает, что очистку нужно повторить.

Видео на сервере GitHub Pages не хранятся, файлы на Яндекс Диске не удаляются. Кнопка очищает данные самого плеера; внутренним HTTP-кэшем браузера управляет браузер.

Есть вложенные папки, поиск, автопереход, сохранение позиции и отметки «Начат просмотр» / «Просмотрено». Галочка в списке позволяет вручную менять отметку. Завершение воспроизведения отмечает видео просмотренным. Длительности MP4/MOV читаются последовательно из ограниченных заголовков, пока основной плеер стоит на паузе; дополнительные скрытые видеоплееры не создаются. При воспроизведении чтение прекращается. Для остальных форматов длительность появляется при открытии видео.

При перезагрузке той же вкладки восстанавливаются открытая папка, выбранное видео, позиция, фильтр и прокрутка. Видео остаётся на паузе. Для этого в `sessionStorage` сохраняется небольшое описание сессии без временных адресов потоков и видеоданных. Кнопка очистки удаляет и эту сессию; очищенный источник не восстанавливается. Доступ к Яндекс Диску нужен и при восстановлении.

В развёрнутом плеере, включая запуск с экрана «Домой», название и управление скрываются через 3 секунды бездействия. Первое касание показывает кнопки и не меняет воспроизведение. Открытое меню скорости, перемотка и управление с клавиатуры удерживают нужные кнопки видимыми. При скрытии панелей размер видео не меняется.

Клавиатура: **Пробел** — пауза, **← / →** — скорость, **Shift + ← / →** — 10 секунд, **F** — развернуть, **Esc** — закрыть меню или свернуть. При фокусе на поле ввода эти сочетания не перехватываются.

## Что означает 32×

Доступны 0.5×, 1×, 1.5×, 2×, 3×, 4×, 8×, 16× и 32×. Браузер определяет максимально допустимую скорость декодирования. Если он не принимает выбранную скорость, плеер включает **обзор с пропуском фрагментов и без звука**, явно показывает этот режим и перемещается только по уже загруженным данным. Короткие события при таком обзоре можно пропустить. Зависание и время фоновой вкладки не накапливаются в последующий скачок.

При недостатке буфера плеер автоматически снижает скорость и показывает фактическую скорость. 32× — целевая скорость обзора, а не гарантия плавного воспроизведения на любом телефоне и соединении. При большом ускорении браузер может отключать звук даже в обычном режиме.

## Приватность и ограничения

- Метаданные запрашиваются напрямую у `cloud-api.yandex.net`, видео — у серверов Яндекса. Через GitHub проходит только загрузка приложения.
- OAuth-токены, пароли и аккаунт GitHub для просмотра не требуются. Закрытые ссылки, пароль и запрет скачивания не поддерживаются.
- История, позиции, скорость и последняя ссылка хранятся в `localStorage` этого браузера. Между устройствами они не синхронизируются. Удаление истории выбирается отдельно в диалоге очистки; файлы на Диске остаются на месте.
- Видео не сохраняются приложением в офлайн-хранилище, но браузер скачивает данные и может временно кэшировать их. Это расходует интернет-трафик.
- Поддержка форматов зависит от браузера и ОС. Для совместимости предпочтителен MP4 с H.264. Серверной конвертации нет.
- Для совместимых HEVC-записей камеры предусмотрена поддержка Safari: плеер проверяет структуру MP4 и наличие VPS/SPS/PPS в конфигурации, затем локальный Service Worker исправляет метку `hev1` на `hvc1` при чтении запрошенных диапазонов. Это не перекодирование и не серверный прокси. Целый файл не загружается заранее; видеоданные не сохраняются в Cache Storage или IndexedDB. Для восстановления после приостановки Safari в IndexedDB хранится только описание текущего потока: временный адрес, публичный источник, размер и позиции правок. Срок действия — 6 часов; при переключении видео описание удаляется, истёкшие записи очищаются при следующем запуске/подготовке потока. Истёкший адрес Диска обновляется напрямую через API Яндекса. Если декодера HEVC на устройстве нет, этот способ не поможет.
- В обычной вкладке Safari на iPhone кнопка разворота использует системный полноэкранный видеоплеер Apple, если его API доступен. Панели браузера скрываются, но собственные кнопки скорости внутри системного плеера недоступны. Для наших кнопок до 32× без панелей Safari добавьте страницу через «Поделиться» → «На экран “Домой”» и запускайте её с иконки. Приложение открывается в режиме standalone; развёрнутый плеер учитывает поворот, видимую высоту и безопасные отступы. История вкладки и приложения может быть раздельной. CSS не может принудительно скрыть адресную строку обычной вкладки.
- Ссылки и имена файлов выводятся как текст. Приложение не использует сторонние CORS-прокси, внешние шрифты или трекеры. CSP ограничивает сетевые запросы API и медиасерверами Яндекса.

## Локальная разработка

Требуется Python 3 для статического сервера; Node.js 22+ — только для тестов. Сайт не требует сборки или установки зависимостей для публикации.

```sh
npm test
npm start
```

Откройте `http://127.0.0.1:8787`. Для работы нужен интернет. Не открывайте `index.html` через `file://`: JavaScript-модули должны загружаться через HTTP(S).

## Публикация

GitHub → Settings → Pages → Deploy from a branch → `main` / `(root)`. Файл `.nojekyll` отключает обработку Jekyll. Сборка и npm-зависимости не нужны. Все пути относительные, приложение работает в подпапке репозитория.

Никогда не добавляйте в репозиторий пользовательские ссылки, видеозаписи, `.env` или токены. Текущий проект не содержит ИИ-обработки и не обращается к локальному серверу другого приложения. Локальные ролики воспроизводятся выбранными файлами браузера и не загружаются на GitHub Pages.

## Проверки

`npm test` проверяет отмену потоков и гонки очистки хранилища, разбор ссылок и вложенных путей, изоляцию отметок разных источников, допустимые адреса медиасерверов, браузерное ограничение скорости и безопасный обзор в пределах буфера. Результаты проверки браузеров описаны в `TESTING.md`.

## Восстановление потока

В Safari поддерживаемые HEVC-контейнеры подготавливаются до передачи в видеоплеер. Совместимый поток отдаёт частичные ответы не более 4 МиБ, включая запросы до конца большого файла. Диапазоны байтов явно передаются через Service Worker: это предотвращает потерю Range в WebKit после первого открытия. Перед чтением заголовка приложение ждёт подключения активного обработчика. Обновлённый Service Worker остаётся в ожидании, пока открыты окна со старым обработчиком: принудительной замены во время просмотра нет. После закрытия окон обновление активируется, а приложение поддерживает совместимый обработчик другой версии; описания потоков сохраняются до подтверждения регистрации. После перезапуска воркер восстанавливает их из локального хранилища, а при его недоступности опрашивает открытые вкладки, включая случай внутреннего идентификатора медиазапроса Safari.

Прерывание совместимого потока вызывает одну автоматическую попытку обновить адрес с сохранением позиции. Повторяющиеся ошибки не создают цикл запросов. Ошибки сети, ограничения API и подготовки потока не объявляются неподдерживаемым форматом. В «Подробностях ошибки» доступны версия приложения, этап, код браузера и статус транспорта; пользовательских ссылок там нет. Ничего не отправляется разработчику автоматически.

При запуске форма доступна после загрузки обработчиков. Если модуль приложения не загрузился, показывается ошибка и ссылка для ручного обновления страницы. Автоматической перезагрузки нет. В справке → «Диагностика сеанса» доступны последние 40 событий этой вкладки: запуск и тип навигации, уход/возврат, смена обработчика, восстановление сессии и ошибки. Журнал хранится в `sessionStorage`, не содержит пользовательских ссылок, имён файлов или временных адресов и никуда не отправляется.


### Браузерные регрессии

```sh
npm ci
npx playwright install --with-deps chromium webkit
npm run test:browser
```

Тест сам запускает изолированный статический сервер, подменяет ответы Яндекс API и использует синтетический синий ролик `tests/fixtures/clip.mp4` (64×64, 4 секунды). Он проверяет смену источников с одинаковыми именами файлов, пустую/недоступную папку, запоздалые ответы, очистку во время загрузки, реальный Service Worker и IndexedDB, две вкладки и сохранение/удаление истории, первый кадр, прокрутку и восстановление сессии. В Chrome, WebKit и моделируемом WebKit standalone дополнительно проверяются сбой загрузки модуля, невалидная ссылка, ошибка загрузки видео с повтором, смена версии воркера без перезагрузки, скрытие управления и первое касание. Пользовательские ссылки, видео и аккаунт не нужны. Для установленного Google Chrome можно задать `CHROMIUM_CHANNEL=chrome`. GitHub Actions запускает модульные и браузерные проверки при push и pull request.
